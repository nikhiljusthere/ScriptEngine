# `page-gen` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `page-gen` CLI command that deterministically generates the *structured* half of a page-campaign batch from `facts.db` (zero manual field-reading), emits the roster declarations + a section-coverage ledger + a verify sheet, and hands only the prose beats to a single subagent — then drives the in-progress **Angel** cluster end-to-end through it (rollout steps 1–2 of the spec).

**Architecture:** One new module, `scriptengine/eval/page_gen.py` (the question catalog, the four emitters, the idempotent batch writer, and the text-insert decl merge), one small helper `parse_page()` in `ingest/crawler.py`, and two Typer commands in `cli.py` (`page-gen`, `page-merge`). Everything is deterministic — no model, no network. The command is a `.py` change, so the full gate triple applies.

**Tech Stack:** Python (the `scriptengine\.venv` venv), Typer, rich, SQLite (`facts.db`), PyYAML (read-only validation only — overrides.yaml is *text-inserted*, never round-tripped), pytest.

**Spec:** `docs/superpowers/specs/2026-08-23-page-gen-design.md`. Read it top to bottom before starting.

- **Rule B — the graphify rule (fast code map).** Put this in every subagent prompt verbatim: *"This repo is graphified — start from `graphify-out/GRAPH_REPORT.md` / `graphify-out/graph.json` (god nodes, module ownership, supersession) and jump to the right file before grepping."*

A `.py` change → **restart the server** (`python -m scriptengine.api.main` on `:8000`; `/health` must show `"device":"cuda"` and list `jjk`).
- **Windows PowerShell 5.1.** No `&&` — use `cmd1; if ($?) { cmd2 }`. Python is `scriptengine\.venv\Scripts\python.exe` (never the system python; no inline `-c` for multi-line — write throwaway scripts to `C:\Users\Nikhil\AppData\Local\Temp\opencode\*.py`). In the **same call** before anything that prints macrons/CJK: `$env:PYTHONPATH="<repo>"` and `$env:PYTHONIOENCODING="utf-8"`.
- **Routing-trap rules (enforced by construction in the catalog, §6 of the spec):** wh-word-first (never a leading "According to X"); "Who" not "Whom"; no "in order to"; no "how many" (counts are attribute lookups or prose-only); no `arc`/`saga` in a roster `match` phrase; singular for relatives; digit-vs-word form must match the page (golds are the stored verbatim fact values, so this holds by construction).
- **No series names in `.py`.** The catalog is keyed to *generic* infobox fact keys; per-wiki specifics live in `series/<name>/overrides.yaml`.
- **overrides.yaml is text-insert only** (3-space `- name:`, 5-space sub-keys, inline `members:` flow list; never a `yaml.safe_load` round-trip write — it destroys the house comments). `yaml.safe_load` is allowed for *validation*.
- **Batch id scheme:** `jjk-pg-<slug>-NNN`, unique across the whole bank (all `questions/*.json`).
- **Battle-scoped technique rosters do not close** (Naoya finding, STATUS row 49): the engine's declared-member filter closes character-scoped technique sets but not battle-scoped ones. The catalog emits battle-technique questions as **qa facts** (gold = the contiguous technique span), never as rosters.
- **Work on branch `character-scoped-questions`, no worktree.** The campaign state (batch JSONs, `overrides.yaml`, the gitignored `series/` corpora) is untracked/uncommitted by design; a worktree would lose it. Per-task commits include **engine files only** (new module, `crawler.py`, `cli.py`, `tests/`). Campaign-state files stay uncommitted until the Angel cluster completes.
- **Auto-retire, never silently re-gold:** any generated question whose gold is not chunked (not present in the `chunks` table) is retired with a reason in the batch's `retired` field (spec §8), mirroring the campaign's G3-shape retires.

```python
def parse_page(paths: SeriesPaths, title: str) -> WikiPage:
    """Parse one stored page with the current extraction code.

    `load_extracted` re-parses a whole corpus; this reads a single page, for
    callers that need one page's current facts and sections without touching
    the rest of the disk. Missing file is a `FileNotFoundError` naming the
    title, because "not crawled" is a different failure from "bad page".
    """
    path = paths.wikitext / f"{sanitise_filename(title)}.json"
    if not path.exists():
        raise FileNotFoundError(f"no stored crawl for page {title!r} at {path}")
    page = WikiPage.from_dict(json.loads(path.read_text(encoding="utf-8")))
    manifest = load_manifest(paths)
    ontology = Ontology.from_dict(manifest.get("ontology") or {})
    return reextract(page, ontology)
```

`scriptengine/eval/page_gen.py` (this task's part; later tasks extend `generate_structured`):

```python
"""page-gen: the deterministic structured half of a page-campaign batch.

The campaign's regular questions -- infobox identity, the per-battle
outcome/location/chapter/technique block, roster sets -- are a pure function
of `facts.db`: the fields are identical in shape across every page. This
module generates them with a provenance marker (`page-gen:<class>:<key>` in
`note`), emits the roster declarations, the section-coverage ledger and the
verify sheet, and merges its output into the one campaign batch without ever
touching a hand-authored question. Only the prose beats (battle "how",
synopsis, relationships, trivia) are left to a reader.
"""
from __future__ import annotations

import re
from dataclasses import dataclass, field
from typing import Any

from scriptengine.config import Settings, SeriesPaths, get_settings
from scriptengine.stores.facts import FactStore

PROV = "page-gen:"
RETIRED_PREFIX = "page-gen-retire"

class PageGenError(Exception):
    """A page that cannot be generated: not crawled, not in the store, or a
    batch that would clobber a hand-authored question."""

@dataclass
class PageGenOutput:
    questions: list[dict] = field(default_factory=list)
    retires: list[dict] = field(default_factory=list)
    rosters: list[dict] = field(default_factory=list)
    coverage: dict = field(default_factory=dict)
    verify: list[dict] = field(default_factory=list)

IDENTITY_FIELDS: dict[str, str] = {
    "status": "What is the status of {name}?",
    "race": "What is {name}'s race?",
    "age": "How old is {name}?",
    "gender": "What is {name}'s gender?",
    "occupation": "What is {name}'s occupation?",
    "class": "What is {name}'s grade?",
    "debut": "In which manga chapter does {name} first appear?",
    "anime debut": "In which anime episode is {name} first depicted?",
    "debutanime": "In which anime episode is {name} first depicted?",
    "voice": "Who is {name}'s Japanese voice actor?",
    "eng voice": "Who is {name}'s English voice actor?",
    "creator": "Who created {name}?",
}
UNCHECKED_KEYS = frozenset({"kanji", "romaji", "japanese"})   # G3 shape, §8 of the spec

def slug_of(title: str) -> str:
    return re.sub(r"[^a-z0-9]+", "_", title.lower()).strip("_")

def chunked(store: FactStore, value: str) -> bool:
    if not value:
        return False
    row = store.connection.execute(
        "SELECT 1 FROM chunks WHERE text LIKE ? COLLATE NOCASE LIMIT 1",
        (f"%{value}%",)).fetchone()
    return row is not None
```

**Files:**

**Interfaces:**
- Consumes: `PageGenOutput`, the existing batch file (if any), `Q.load_file`/`Q.validate` (`eval/questions.py`) for the final validation pass.
- Produces: `write_batch(batch_path: Path, series: str, slug: str, wiki: str, out: PageGenOutput) -> dict` — returns the written batch dict. Rules:

1. **Read the existing batch** (if present): keep every question whose `note` does **not** start with `page-gen:` (hand-authored + prose), and every `retired` row whose `reason`/`id` is not `page-gen`-marked.
2. **Reconcile collisions:** a kept question whose **normalized question text** (NFKD-fold, lowercased, punctuation-stripped) equals a generated question's normalized text is superseded: move it to `retired` with `reason: "superseded by <generated note> (page-gen reconciliation)"` and drop it from `questions` (the generated one takes its place). 4. **Header:** `{"series", "wiki", "updated": <today>, "note": "...", "retired": [...], "questions": [...]}` — `note` records the generation (count, date, that the structured half is `page-gen:`-marked).
5. **Validate:** `Q.load_file` + `Q.validate([bank])` on the written file; on `QuestionsError` raise `PageGenError` with the validator's message (a generated batch that does not validate must not be written — write atomically: build in memory, validate the serialized JSON, then write).
