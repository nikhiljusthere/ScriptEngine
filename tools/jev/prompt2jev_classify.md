# prompt2jev: `ingest/classify.py` as typed decisions

The conversion package prompt2jev (sumleo) produces, for the one prompt in the
repo that is already a closed question: `_TEMPLATE` + `SYSTEM` in
`scriptengine/ingest/classify.py` (PROMPT_VERSION `2026-08-03.2`). Nothing in
`classify.py` is changed; this is the drop-in candidate and the evidence for
whether to adopt it.

Files beside this note, in `tools/jev/prompt2jev/`:

- `classify_request.json`: the request, validated with `prompt2jev validate --strict`
- `classify_decide.py`: generated by `prompt2jev code --lang python-stdlib` (stdlib only, reads `TYPESAFE_BASE_URL`, so it hits the local gateway)
- `classify_run_fastlane.json`: the real output of one live run on the fast lane

## 1. Decision contract

- **Decision**: the page's `semantic_type` and its eight boolean `PROPERTIES`, stored at index time and never asked at query time.
- **Evidence unit**: one ability page. The state is `_context()` verbatim (title, categories, class field, known users, inventor, lead ≤ 1,200 chars).
- **Consumer**: `classify_series()` stores the row, which `roster` / `semantics` read to reject or annotate members (never add).
- **Unknown path**: `semantic_type = unknown` is an offered option, and any noul inside the no-judgment band (0.2–0.8 here) stores no property, the same as a key missing from today's JSON.
- **Success check**: agreement with the stored LLM classifications on the pages `needs_classifying()` picks, then `canon-run` precision unchanged or better.

## 2. Split table

| Instruction in the prompt | Became | Id |
|---|---|---|
| `semantic_type must be one of: {types}` | `choice`, 13 options incl. `unknown` fallback | `semantic_type` |
| race_exclusive (+ trigger clause) | `noul`, the trigger clause in `criteria.true` | `race_exclusive` |
| biologically_intrinsic (+ latent potential clause) | `noul` | `biologically_intrinsic` |
| externally_granted (+ "a trigger is not a grant") | `noul`, rephrased without negation for the lint | `externally_granted` |
| teachable, stackable, temporary, requires_artifact, requires_fusion | one `noul` each | same names |
| "Judge the entity itself, not the beings who used it" | `instructions.focus` on every question | all |
| Title / categories / class / users / inventor / description placeholders | `state.entity.*` fields | state |
| `"reason": "one sentence"` | `keep-llm` (Jev does not generate); the stored reason becomes the answer's probabilities | - |
| "JSON only, no fences" (SYSTEM) and the output shape | `drop`: the answer is already typed | - |
| "precise about is vs can be given" (SYSTEM) | folded into `externally_granted` / `biologically_intrinsic` criteria | - |

## 5. Assumptions and fixtures

- **Not ready to replace the LLM call.** One confident wrong property
  (`requires_fusion`) on the canonical hard case is exactly the precision cost
  the "reject or annotate, never add" rule was written to bound. Adopt only
  after `jev-calibrate` gives each property a `gate` or
  `gate-above-confidence` verdict on labelled pages (the stored
  classifications are the label source; see `calibrate_bank.md` for the
  procedure).
- The deep lane (NInfer, `--model deep` / `X-Jev-Lane: deep`) answers the same
  request as one-hot text parses with `confidence: null`. It is a check, not a
  calibrated replacement.
- Thresholds in the generated file (`noul_yes 0.8`, `noul_no 0.2`) are
  prompt2jev's illustrative defaults, not tuned.
- Fixtures to label before automating: Great Ape (race-exclusive, intrinsic,
  not stackable), Super Saiyan (intrinsic, teachable = no), Spirit Bomb Super
  Saiyan (granted, stackable), Kaio-ken (teachable, power-up), Potara fusion
  (requires_artifact, requires_fusion), and one page with an empty lead
  (`unknown` expected).
